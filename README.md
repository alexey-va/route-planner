# Route Planner

Веб-приложение для построения маршрута на Яндекс Картах и расчёта стоимости
доставки по расстоянию, весу, машине, времени, дню недели и сумме заказа.

Production: <https://route.alexeyav.ru>

## Возможности

- построение маршрута и определение расстояния;
- переключение между новым и классическим интерфейсами;
- учёт географических зон из `data.geojson`;
- выбор машины по грузоподъёмности;
- расчёт тарифа и объяснение применённых правил;
- валидация параметров и автоматический подбор доступной машины;
- локальная история расчётов;
- закрываемая справка по тарифам и внутренним подсказкам.

Приложение работает полностью в браузере. Отдельного Node.js/Express backend
в этом репозитории нет.

## Стек

- React 18;
- Vite 5;
- Tailwind CSS;
- JavaScript/JSX;
- API Яндекс Карт;
- Vitest и Testing Library.

## Локальный запуск

Требуется Node.js и npm.

```bash
npm install
npm run dev
```

Vite использует порт из `vite.config.js`. Адрес dev server нужно брать из
вывода команды, а не считать фиксированным.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | локальная разработка |
| `npm test -- --run` | однократный запуск тестов |
| `npm run test:ui` | интерактивный Vitest UI |
| `npm run test:coverage` | покрытие тестами |

## Архитектура

```text
src/
├── App.jsx             # состояние и экран калькулятора
├── Test.jsx            # интеграция с Яндекс Картами
├── script.jsx          # тарифный движок и конфигурация машин
├── components/         # история, правила и справка
├── hooks/              # persistent state и доступ
└── utils/              # валидация и чистые расчёты
```

Тарифы меняются в `src/script.jsx`. Компонент справки читает ту же
конфигурацию, поэтому новые правила не следует дублировать вручную в UI.

Подробные инструкции для разработки: [`AGENTS.md`](AGENTS.md).

## Данные и конфигурация

- `data.geojson` — зоны доставки, копируемые в итоговый Docker image;
- `index.html` — подключение браузерного API Яндекс Карт;
- `src/constants/adminAccess.js` — локальная защита внутренних подсказок.

Клиентские значения доступны пользователю браузера и не должны считаться
серверными секретами. Ключ Яндекс Карт следует ограничивать доменами в
настройках провайдера.

## Деплой

Woodpecker запускает `deploy-route-planner.sh` при push в `master` или вручную.
Dockerfile собирает статический Vite bundle и раздаёт его через `serve` на
порту 3000.

Классический интерфейс используется по умолчанию. Новый интерфейс доступен через
переключатель «Новый» или параметр `?ui=modern`. Точный снимок классического
интерфейса хранится как статическая сборка в `public/legacy/`.

## Откат интерфейса

Состояние production перед современным редизайном сохранено тегом
`route-before-modern-ui-2026-07-25`.

Предпочтительный откат сохраняет историю и запускает обычный production deploy:

```bash
git switch master
git pull --ff-only
git revert --no-commit route-before-modern-ui-2026-07-25..HEAD
git commit -m "revert: restore classic route planner"
git push origin master
```

Команда откатывает все изменения после контрольной точки, включая последующие
исправления редизайна. Перед push результат можно сверить с тегом:

```bash
git diff --exit-code route-before-modern-ui-2026-07-25
```
